Surfaced from the agent seat at the it-8k3p landing, 2026-08-21, as a reflection rather than a finding, and lifted here because it shapes what gets built rather than any one build.

Composed prose splits by species and the split has a cost the design never priced. A ratified PROMPT string lives in src/framings.rs; an inline REFUSAL string lives wherever it fires. So an arc whose lease covers the code it repairs can always afford a refusal, and can only afford a prompt if the dispatcher happened to lease framings.rs too. The instrument an agent reaches for is therefore chosen partly by the write-set it was handed, not only by which instrument is right.

MEASURED IN THIS ARC. it-8k3p landed a refusal on malformed written form, which was correct. The same arc could not build the prompt its residue wanted — a name whose first letter is not a PowerShell escape letter loses its backticks and nothing else, arriving as a legal plain title nothing can detect, which wants a nudge at the vein mint rather than a refusal at all. That string belongs in framings.rs, which sat outside the lease, so the residue was filed as it-d4bh instead of built. The dispatcher who wrote that lease (this seat) never considered framings.rs, because nothing in the fire suggests it.

WHY IT MATTERS BEYOND ONE ARC. dc-grrb rules that vein landmarks are presence prompts, never gates — the house has a standing preference for prompting over gating in a whole class of surfaces. A structural bias toward refusals therefore pushes against a user ruling, quietly, one lease at a time. Nobody chose that; it falls out of where the two kinds of string happen to live.

THE CHEAP HALF IS DISPATCHER DISCIPLINE and costs nothing: lease framings.rs on any arc whose repair might plausibly want a prompt. This seat is adopting that from now. But discipline is the road this system rejects elsewhere, and a dispatcher cannot always foresee which repairs will want prompting — the it-8k3p fire could not have.

THE REAL FORK IS THE USER'S, because it touches the ratified register: whether the framings/inline split should track SPECIES (prompt vs refusal) at all, or whether it should track RATIFICATION (user-ratified prose in framings, arc-composed prose inline, whichever kind it is). The second reading would put a new prompt inline on the dc-vzvf flag channel like any other composed string, and move it to framings only once the user ratifies it — which is what the flag channel already does for every other composed string. That would remove the bias without loosening the pen. Filed as an observation, not a proposal: this seat holds no design pen, and the split is dc-vzvf's ground.

Neighbourhood: it-8k3p for the arc that measured it, it-d4bh for the prompt it could not build, dc-vzvf for the register the fork touches, dc-grrb for the standing preference it pushes against.
