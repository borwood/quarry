The residue it-8k3p left open, stated in cl-j2pk and unbuildable inside that arc's lease.

MEASURED 2026-08-21, in PowerShell, the shell every session here runs: "`slug-follows`: y" arrives as "slug-follows: y". Where a backticked name's first letter is one of the escape letters (r n t a b f v 0 e) the escape leaves a control character behind and cl-j2pk's floor refuses it. Where it is any OTHER letter, PowerShell simply drops the backtick and keeps the character, so BOTH backticks vanish and what reaches q is a legal plain title. No check at the receiving end can tell it from a title that was typed that way.

WHAT IT COSTS. The name never enters the register: dc-qvtz's backticked join never fires, so the vein is invisible to relatedness and intent-delta, and the vein prompt keyed on the same shape (cl-sv7z at mint, cl-vuda at harvest) stays silent — a kindless vein mint with an eaten name draws no question at either station. The claim reads fine to a human and is inert to the machine.

THE CURE THAT IS LEFT is a prompt, never a gate (dc-grrb): a claim minted --kind vein (or --kind feature) whose title carries no backticked register name draws the register-form question at the same choke point that already carries SPECIES_PROMPT and VEIN_PROMPT — naming the form and the single-quote road, since an eaten name and a deliberately plain one are indistinguishable and only the author knows which it is. It is the exact inverse of cl-sv7z's prompt, at the same surface.

WHY IT WAS NOT BUILT AT it-8k3p. The prompt's line is a composed register string and those ride src/framings.rs (dc-vzvf's flag channel), which sat outside that arc's write-set; the refusal texts it-8k3p did land are inline bails, which is why the floor was buildable and the prompt was not. The teaching half landed instead: q claim --help and q set --help now state single quotes as the rule for a backticked value.
