Raised by the it-2eqk brief as worth deciding while there, and deliberately left standing: the narrow fix (queries::landmark_globs, cl-8h8j) drops only the ARC'S OWN RETURN from the land-time landmark check, restoring the prompt for dispatched landings. The clause itself is untouched.

The clause: queries::files_cited returns true when any claim or doc carries a file: edge into the checked globs, OR when a DOC'S OWN PATH falls inside them. That second half is why the leased return silenced the prompt, and it is broader than the return. Any registered doc living inside the code the arc touched — a spec beside the module it specifies, a protocol file, a journal entry committed under a touched glob — reads as citation of that code, with nothing said about the capability that landed.

The call is the user's because dc-grrb rules this check: PRESENCE of citation, never quality; a prompt, never a gate, because a blocked done breeds Goodhart claims. Tightening the clause narrows what presence MEANS in a user-ruled construction — the arc-report exclusion was a defect repair with a measured silence behind it, but "a doc at a touched path is not a citation of the code there" is a semantics change, not a bug fix.

The shape of the fork, if it is ever taken: keep the doc-path clause (a doc at a path is genuinely about that path, and quality is judged at review), or require a real file: EDGE from every citer and let a doc's own path count for nothing. The looseness costs a silent prompt wherever a doc happens to sit inside landed code; the tightening costs the prompt firing at landings a doc really does describe.
