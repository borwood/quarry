Two session kinds, conventional first: decisions (rulings, design, the thread queue) and dispatching (ready consumption, in-flight stewardship, harvest, homework residue). Kind lives in the charter until orientation consumes it - structure follows kind-on-consumption. A decisions session firing hot is legitimate dispatch: the preferred flow hands ready work to a live dispatching session; when none is live, offer to launch one (launcher script) or fire solo. q dispatch is definitionally a hand-off - building in-loop rides the solo path (brief + reserve), never a silent fusion. Parallel dispatch is the normal shape ("are these parallelizable items? fire them all off"); the single-slot badge is a regression against it, and per-chat badge state (it-u8uf) is a precondition, promoted to debt.
