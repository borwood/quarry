Defining a session IS making it re-enterable — via the optional launcher or by the user naming it and the agent adopting; the registry entry is the persistence, the launcher just one door. Ephemeral (this chat only) is the odd case, flagged at creation and asked about explicitly. When a chat starts unbound in a repo with registered sessions and the user launches into substantive work, the agent asks before the first graph write: adopt an existing session, or define a new one — and if new, persistent or ephemeral? The orient hook carries this reminder so it never depends on agent memory.
