# the user register corpus

Seeded 2026-08-11 under the thread "the user's register over time" (th-6vva),
deliberately before the consuming system has shape. Purpose: accumulate the
user's reasoning and style — how they decide, not just what they decided — so
a future system can resolve low-impact calls in their register. Entries are
dated; verbatim where possible; each with context and register notes.
Observation, not judgment: the corpus records how the user actually reasons,
never how an agent wishes they would.

## 2026-08-11 — the surfacing-audit session

**Verbatim, closing the audit** (which had found ~30 handrolled node-surfacing
registers, no shared atom, and a confabulation traced to an area-less search
hit):

> I should have spent more time laying out project structure in the first
> session, and that's on me. This is a fatal pattern and is part of what
> prompted the start of this project.

**Verbatim, on setup-time vocabularies that rely on agents choosing to comply:**

> discipline decides to create contracts, and discipline to me means "bet
> that it won't happen"

**Register notes observed this session:**

- Takes structural omissions on themselves rather than on the agents; names
  recurring failures *fatal patterns*, not misfortunes.
- Prefers enforcement by construction over doctrine or discipline; the
  question put to any proposal is what makes skipping it impossible, not
  what makes doing it likely.
- Probes designs by first-principles walkthrough: grants a premise
  explicitly ("grant it for now"), demands yes-or-no, then pros and cons —
  before accepting any frame.
- Verifies provenance rather than trusting fluency: caught a confabulated
  citation by checking a node's about edges; expects assertions to be
  checked against the graph, not remembered from conversation.
- Names conversational pressure when they feel it ("your options have a
  certain pressure beneath them to close this out"); wants threads held
  open honestly rather than driven to closure.
- Rules via compact packages — yes/amend per numbered point; asks
  clarifying questions before ratifying rather than rubber-stamping; reads
  proposals closely enough to catch architectural inconsistency in them
  (the unpack register left outside the shared constructors).
- Asks for data before position: demanded harness behavior be measured
  before building a design on assumptions about it, and discarded the
  finding without sentiment when it proved irrelevant.
- Scopes sessions honestly ("we won't get to other threads tonight");
  reads foundational discoveries as wins, not setbacks ("we moved some
  rocks and found serious foundational work").
- In prose, ids mean nothing to them — titles only; ids belong to commands
  and node bodies. Conversation is single-thread by standing ruling.

**Decision heuristics, candidate until confirmed by recurrence:**

- If a mechanism relies on an agent choosing virtue mid-task, assume it
  fails; redesign so the cheap path is the correct path.
- Optionality is suspect for foundational machinery ("not sold on it but
  not disgusted" — optional tends to mean unadopted).
- A structural lesson generalizes: one instance of a pattern (area-less
  find hits) warrants auditing the whole class (every surfacing register),
  not patching the instance.
