## Reflections

The chicken-and-egg (a hook in a fork can't find the canonical store to look up where the canonical store is) forced the pin file **outside** any store — user-level state is new machinery, the first quarry state not living under a graph, worth watching. `clear_pins` matches roots by display-string equality; a case-mismatched cwd could leave a stale pin — stale pins stay *truthful* (they name the right root), so the failure is hygiene, not misdirection. The guard's rel-path computation trusts the hook input's `cwd` for work-root discovery with process-cwd fallback; if some harness runs hooks from neither the fork nor provides cwd, a fork write's rel would strip against neither root and go unjudged — allowed-not-denied, the safe direction, but unobserved. Surprise: how much of the chain was already constructed — the only genuinely new joint was *where the pin sleeps*; everything else was re-plumbing existing seams through one function, which is the decision working as designed.
