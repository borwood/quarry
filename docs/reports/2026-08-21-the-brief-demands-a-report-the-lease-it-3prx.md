# dispatch report: the brief demands a report the lease forbids (it-3prx)

The fix is the first of the two the item named: **the dispatch station adds the report path to every lease it takes.** It is not quite one line — the report is now derived, leased, named in the brief, and printed back at harvest — but it needs nothing from the item, and the second candidate (a reconciliation that can read a report nobody registered) stays unbuilt and unneeded.

## Outcome, against the acceptance line

> a dispatched agent can register its own report from its own seat: the lease a dispatch takes covers the report path the RETURN spec demands, and harvest reconciles the declared user-owned calls without a dispatcher writing the doc node by hand

Met, end to end, pinned by `the_arcs_report_path_is_leased_at_the_fire_and_registers_from_the_agents_seat` in `tests/basic.rs`. The suite is green: **133 passed in tests/basic.rs**, and 2 / 1 / 1 / 1 / 3 across broken_pipe, observed_set, store_lint, surface_lint, worktree_proof — 141 total, 0 failed.

What the arc actually built:

- **`coord::arc_report_path`** derives one path per arc at the fire: `docs/reports/<date>-<slug>-<item>.md`, the reports register's own shape, with the item id carrying uniqueness. A re-dispatch takes the next free `-arcN` name rather than the file its predecessor left behind — a prior arc's report is a registered doc whose blob stamp still names that path, so overwriting it would make one of the two records a silent lie. (This is what the it-rmqy dispatcher did by hand as `-arc2`; it is now derived.)
- **`ops::dispatch`** points the lease at it through `coord::set_arc_report` + `coord::set_lease_globs`. Every arm re-points, so a re-dispatch and a steal both get the current arc's return, not their predecessor's.
- **`render::brief`** names the path in the RETURN spec and hands over the filled-in `q new doc … --kind report --path <path> --about <area> --supports <item>` command — the registration is delivered where the work is understood, not memorized.
- **`render::harvest`** prints the same exact `--path` in its homework — or, when `queries::latest_report_doc` already finds this arc's report, says it is registered from the agent's own seat and asks for nothing, so one report never mints two doc nodes.
- The arc report path is filtered out of harvest's *leased but untouched* enumeration: an unwritten report is a missing return, not "dead weight in the lease".

The vein is **cl-ue2e** (`leased-return`), sourced to `src/coord.rs`, supporting it-3prx.

## Two design calls worth the dispatcher's eye

**One path per arc, never the zone.** The item's note ("a shared lease is wrong here — two arcs writing distinct report files need no co-write zone, only their own paths") turned out to be load-bearing in a stronger way than it reads. `coord::globs_overlap` compares *static prefixes*, so a `docs/reports/**` glob on every dispatch would (a) let every agent write its neighbours' returns and (b) make a second session's dispatch refuse outright at C7. Concrete per-arc paths never prefix one another, so concurrent arcs are invisible to each other by construction.

**The arc report is exempt from contention, deliberately, in two places.** It joins the globs *after* `coord::reserve` rather than inside it, and `coord::lease_overlaps` now skips arc report paths on both sides. Without the second exemption, any write-set covering `docs/**` refuses against every live arc's return — this is not hypothetical, it broke `join_cli_env_identity_transport` on the first build, where a `docs/**` dispatch could no longer fire while another arc flew. The justification: there is nothing to contend for (the path is unique to the arc and names a file that does not exist yet), and the write guard never offered that protection anyway — a badged write is judged against the *badge's own* lease, foreign exclusivity unconsulted (`teach::lease_check`, first branch).

Both are named in cl-ue2e's body so the next reader meets the reasoning, not just the code.

## Findings, each disposed (dc-cbkq)

1. **The leased return silences the land-time vein prompt** — filed as **it-2eqk** (kind bug, blocked on it-3prx). Measured, not reasoned: with the report path leased, the agent's report accrues into the observed set (correctly — cl-up6s's no-silent-discard invariant), `main.rs`'s `vein_check` takes the observed set as its globs, and `queries::files_cited` counts *a doc whose own path falls inside those globs* as a citation. The registered report is exactly such a doc, so every dispatched landing whose agent registered its report satisfies the check trivially and the dc-grrb landmark prompt goes silent. A throwaway instrument confirmed it (prompt fires; register the report doc, changing nothing else; prompt silent) and was deleted. The fix is one line at the consumer — filter `coord::is_arc_report` out of `vein_check`'s globs, the predicate already exists — but `src/main.rs` and `src/queries.rs` sit outside this write-set, which is why it is filed rather than fixed. **This is the one thing I would not land without: it is a live degradation of a ratified mechanism, introduced by this change.**
2. **The registering hand** — filed as **th-bguq** (see user-owned calls below).
3. **A dispatcher-passed concrete report path is replaced, not kept.** `set_arc_report` drops any concrete `docs/reports/*.md` glob when it points the lease at the arc's own. If a dispatcher deliberately leased an *existing* report file (to have an agent amend a prior report, say), that glob is silently swapped. Discharged, not filed: it is visible in the dispatch echo and the brief's `leased:` line, a pattern glob (`docs/reports/**`) survives untouched, and the alternative — a per-item family test, or a separate `report` field on the Lease with its migration — buys precision nobody has asked for. Filing it as a watch would breach dc-ygzz's boundary (watch is for compromises with a named trigger); if it ever bites, it is a bug on sight.
4. **`cl-p6aj` (`q-dispatch`) now under-describes its own act.** Its one-act sentence enumerates brief, lease, in-flight, token, spawn line — the lease now also carries the arc's return. Affirmed as still-true rather than amended: a claim body is the harvester's pen, and cl-ue2e carries the new sentence. Named here so the amendment is a choice, not an omission.
5. **Report filenames change shape.** Derived slugs come off the item title (capped at 40 chars, cut at a hyphen boundary), where the existing directory carries short dispatcher-chosen slugs (`glob-shape-floor`, `spawn-line`). This report is written at the derived path as its own proof. Discharged: nothing in the graph or code prescribed the old shape, and a derived name is what makes the `--path` in the brief and the homework exact.

## user-owned calls:

- **The registering hand.** dc-kpqg (user, in force) places report registration **at harvest**: "registered as a doc at harvest; registration is one homework command; the dispatcher judges whether a given report earns it (prompt, never gate)." This item's acceptance line says the agent registers from its own seat, and building it moves the dispatcher's earns-it judgment from a gate at registration to a review after it. Filed as **th-bguq**. The provisional path taken is the least-committal one consistent with standing rulings: the brief *invites* registration and nothing gates it (dc-kpqg's "zero obligatory q acts" stands — no verb refuses an unregistered arc), harvest still shows the report at the judgment seat and says the record stands unless the dispatcher drops it, and cl-hct3 already names agent registration as an expected road ("a report is honestly registered by the agent under its badge or by the dispatcher afterward, so who wrote it is no join key"). Nothing was settled or superseded. If the user affirms the shape, dc-kpqg's report paragraph wants its sentence amended to say so.

## Reflections

The satisfying part of this repair is that the contradiction was structural and small: the machine demanded an artifact and then forbade it, and nobody could see it from either seat alone — the dispatcher saw a report arrive and wrote the doc node by reflex, the agent saw a denial it had no power to fix. It took three arcs to become an item. I keep thinking about what else has that shape: a demand and a permission that were built in different sessions and never met.

The thing I got wrong first was reaching for `docs/reports/**`. It is the obvious lease, it is what this very dispatch was fired with by hand, and it is wrong in a way that only shows up under parallelism — which is the normal shape here. The item's one-sentence note about co-write zones saved me; I would have shipped the broad glob otherwise, and the failure would have surfaced weeks later as "why does dispatch refuse while another agent is running".

What I am least comfortable with is it-2eqk. I introduced a real degradation of a ratified mechanism and could not fix it, because the two lines that need touching are outside the write-set. That is exactly the shape of the item I was dispatched to fix — a contract that mandates something and a lease that forbids it — one turn out. The honest reading is that a write-set drawn around "the files the fix touches" cannot anticipate the files the fix *consequences*, and the only channels an agent has for that are the filed item and a loud paragraph in the report. Both used. But it does mean the landing ships with a known live defect for as long as it takes to dispatch it, and I would understand a dispatcher who fixed those two lines by their own hand before flipping done.

Smaller notes: the `-arcN` suffix is decided by looking at the filesystem, not the graph — a report file that exists unregistered still pushes the next arc along, which I think is the right direction of caution (never clobber) but is worth knowing. And the derived slug from a long title reads a bit truncated ("the-brief-demands-a-report-the-lease"); the filename is honest but the human-chosen slugs in the directory read better. If that grates, the cheapest fix is a `--report-slug` on dispatch, not a cleverer slugifier.
