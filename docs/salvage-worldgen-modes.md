# Worldgen modes and component seams (salvage pre-planning)

Recorded 2026-08-09 from the user's framing in the salvage-opening
conversation. This is the feature map the fresh repo's bones must imply —
the seams between named components, swappable behind APIs by responsibility.

## The top-level divide: deep-core vs pure-core

The engine splits along a general **deep-core vs pure-core** divide, and the
naming register encodes it (ruled 2026-08-09). Deep-register names —
`deep-` prefixed, geological, hard-science — mark the gentime-forward side:
process, depth, complexity. Pure/magic-register names mark what is
immediate, built on compromise, runtime-forward — bending religious at the
extreme (pure vision, manifestation). Other modules bend philosophical,
ecological, anthropological, linguistic by the problems they solve, each
with a deeptime or puretime valence. The divide does not foreclose modules
from either grouping functioning together. A module's name register is
therefore a legible signal of its runtime posture.

## The modes the engine will support

1. **Infinite from seed** — pure chunk generation, no deepcell grid (the
   Minecraft / Vintage Story pattern). Unbuilt today. Working name:
   **pure-lands**.
2. **Bounded with deep-time** — a bounded world generated by the
   pre-gameplay runner, giving global cohesion. All worldgen work so far
   lives here. The deep-time pass runner pre-generates a bounded grid of
   deepcells (core samples) and unlocks the cold deepfield LOD — cold LOD
   wherever deepcells are resident.
3. **Runtime core-sample** (the middle path) — pure runtime generation,
   still deepcell → refinement based, allowing halo sampling methods but no
   global cohesion from deep-time passes. Why want it: layer-based regional
   generation with better regional cohesion than pure chunk generation. A
   runtime-only core-sample world could still generate deepcells spanning a
   greater radius than live chunks.

## Component reading

- **core-sample** (named by the user, 2026-08-09): the runtime deepcell →
  refinement pipeline. Modes 2 and 3 build on it; mode 1 bypasses it.
  **Refinement is a sub-feature of core-sample, not a top-level seam** —
  it is the upscaling/interpolation of facts from the deepcell grid into
  immediate chunks, intrinsically tied to deepcell worlds.
- **deep-time pass runner** (name pending — possibly just deep-time): its
  own feature, composing with core-sample; pre-generation for bounded
  worlds.
- Chunk generation without deepcells is its own component seam (mode 1,
  pure-lands), unbuilt.
- The cold **deepfield** LOD is unlocked by deepcell residency, however
  that residency was achieved.
- **augury** (working name, from deepcraft sketches): collapse-based
  simulation of distant events — civilizations especially, natural
  phenomena implied — tied to the fact ledger system and theorized around
  the deepcell framework. Puns auger, the core-sampling tool. Sits across
  the divide: a runtime system reading gentime facts, the worked example of
  the runtime↔gentime relationship.

## The product shape

A game is a plugin pack that includes a plugin layer for its launcher.
The engine ships with plugins built on engine modules — opinions on common
game needs, inspired by other voxel games and their modding communities.
Shipped games can carry their own launcher and world menu; the engine's own
launcher, editor, and plugin marketplace (all unbuilt) are opt-in surfaces,
because people should own what they make.

## The architectural directive

Nothing ports untouched: salvage lands the useful parts of deepcraft in a
new substrate whose organization is the point. The general graph of the
project implies these seams; APIs allow swapping the component that handles
each responsibility.
